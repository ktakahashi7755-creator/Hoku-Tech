## 1. 目的

ITS 合同会社が IT 未経験者を採用・教育し、成長を定量的に把握できる学習基盤を作る。
「見栄えの良いデモ」ではなく、データが保存され、権限が守られ、講師が毎日使える運用ツールであること。

## 2. 利用者と主なユースケース

| ロール | 主なユースケース |
|--------|------------------|
| STUDENT (受講生) | 次にやることを知る / レッスンを読み演習する / 理解度チェックに合格して完了する / 課題を提出・再提出する / 自分の進捗とレビューを確認する |
| INSTRUCTOR (講師) | 担当受講生の状況把握 / 停滞者の発見 / 課題をルーブリックで採点 / コメント・スキル評価を記録 / CSV 出力 |
| ADMIN (管理者) | 全受講生の把握 / 受講生追加 / 担当講師・学習期限の設定 / 停滞閾値の設定 / 教材の公開管理 / 監査ログ確認 |
| SUPER_ADMIN | ADMIN の全機能 + 管理者ロールの付与 (付与 UI は未実装、§6) |

## 3. 原則と、それを満たす仕組み

| 原則 | 実装 |
|------|------|
| 説明なしで操作できる | ナビは 6 項目。ホーム最上部に「次にやること」と 1 つのボタン |
| 次に何をすればよいか常に分かる | `nextAction()`: 修正依頼 → 学習中のレッスン → 前提を終えた課題 → 未学習レッスン → レビュー待ち の優先順 |
| 管理者が全員の状況を即座に把握 | ダッシュボード (停滞・レビュー待ち・修正依頼) と受講生一覧 (A〜E 指標) |
| 読むだけでなく実装して理解 | 全レッスンに演習・実行済みコード・理解度チェック。課題はコード / GitHub 提出 |
| 見た目だけのダッシュボードにしない | 全指標は DB の記録から算出。E2E テストで「操作 → DB 保存 → 再表示」を検証 |
| 進捗データの永続化 | PostgreSQL。LocalStorage は使わない |
| AI 拡張を妨げない | 評価・提出・レビューが構造化データ。AI 補助は「提案」として同じテーブル構造に追加可能 (§7) |
| 本番品質・セキュリティ | サーバー側認可、argon2id、DB セッション、ログイン試行制限、監査ログ、CSV インジェクション対策 |
| 各フェーズで動作検証 | 単体 43 件 / E2E 12 シナリオ / 教材コード実行検証 15 件 (2026-11-06 時点) |

## 4. 進捗の定義 (ページを開いただけでは完了にしない)

| 指標 | 定義 | 算出元 |
|------|------|--------|
| A 教材履修率 | 「学習完了」したレッスン / 公開中レッスン。完了は**現在の版の理解度チェック合格**がサーバー側の条件 | `lesson_progress` + `quiz_attempts` |
| B 課題完了率 | 合格した課題 / 公開中課題 | `submissions` (最新の提出) |
| C 理解度評価 | レッスンごとの理解度チェック最高点の平均 | `quiz_attempts` |
| D 実装能力評価 | コード系課題 (CODE / GITHUB_REPO / PROJECT / FINAL_PROJECT) の最新採点の平均 | `reviews` |
| E 実務準備状況 | 講師のスキル評価 (9 観点・1〜5) の最新値の平均 × 20 | `skill_assessments` |

* 指標は混ぜた総合点を作らない。データがない指標は 0 ではなく「未評価」。
* 学習時間は表示するが、どの指標にも使わない (時間が短いことを能力不足と扱わない)。
* 学習停滞 = 最終学習日から閾値日数 (既定 7 日・管理者が変更可) 以上。表示は「停滞の可能性」とし、講師には「状況確認の連絡」を提案する。

## 5. 課題とレビュー

* ステータス: 未着手 (提出なし) / 取り組み中 (DRAFT) / 提出済み / レビュー待ち (IN_REVIEW) / 修正依頼 / 再提出 / 合格 / 不合格
* 採点は 7 観点のルーブリック (要件充足 25・正確性 20・可読性 15・保守性 10・テスト 10・セキュリティ 10・説明能力 10)。配点と合格点は課題ごとに設定。
* 合計が合格点未満なら「合格」を選べない (サーバー側で検証)。
* 採点は追記のみ。採点時点のルーブリックと合格点をスナップショットとして保存するため、後からルーブリックを変えても過去の評価は変わらない。
* 提出・再提出・採点のたびに相手に通知、操作は監査ログに記録。

## 7. 将来の AI 機能 (L8) との接続点

| 機能 | 接続点 | 制約 |
|------|--------|------|
| AI チューター | レッスン本文 (構造化 JSON) と学習履歴を入力にする | 個人情報は送らない。回答は「ヒント」とし完了判定に使わない |
| AI コードレビュー補助 | `submissions.text` / `repoUrl` を入力、出力は講師画面に「下書きコメント」として表示 | `reviews` への書き込みは講師の確定操作のみ。合否は人が決める |
| AI 学習計画・弱点分析 | `getStudentOverview()` の出力 | 提案として表示し、講師が採否を決める |
| AI 教材改善提案 | `quiz_attempts` の誤答傾向 | CMS の下書きとして提案、公開は講師 |
