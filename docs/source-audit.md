## 1. 結論 (要約)

* 公開教材は **72 記事**。一覧 8 ページ (9 件 × 8) と WordPress REST API (`X-WP-Total: 72`) の
  URL 集合が完全一致し、**漏れなく全件の本文を取得できた**。
* 構成は「はじめに → 環境構築 → Java 初級 → Java 中級 (OOP) → HTML/CSS → JSP/Servlet →
  SQL/JDBC → MVC → Spring Boot」。スキルチェックは SC1・SC2・SC3 の 3 本で、
  **SC3 (図書管理システム) が実質の最終制作課題**。
* **サンプルコードと実行結果のほぼすべてが画像** (テキストのコードブロックは 72 記事中 1 記事に 1 個のみ)。
  コードはコピーできず、検索もできず、スクリーンリーダーでも読めない。正しさも機械的に検証できない。
* 画像 833 枚のうち **712 枚が `lh7-rt.googleusercontent.com` へのホットリンク**
  (Google ドキュメントから貼り付けたもの)。元データが消えると画像も消える。**alt テキストは 833 枚中 831 枚で空**。
* 動画は 0 本。
* 記事単位では **「維持」(そのまま使える) は 0 件**。改善 44 件 / 再構成 28 件。
  改善優先度は高 30 / 中 36 / 低 6。
* 事実誤り・古い手順・セキュリティ上の問題が全レベルにある (§5)。特に
  PostgreSQL の認証無効化手順 (No.70) と、SQL インジェクション対策の説明がないこと (No.60, 61) は、
  公開前に必ず直す必要がある。
* REST API・単体テスト・チーム開発 (PR / レビュー)・認可 (ロール)・JavaScript は**教材が存在しない**。

### 5.3 古い前提

* Tomcat 8.0 (No.42) と Tomcat 10 (No.37) が混在。Tomcat 10 以降は `jakarta.*` 名前空間が必要だが、
  どちらで書かれているかはコード画像のため確認できない。
* Java EE の表記のみで Jakarta EE に未言及 (No.41)。Internet Explorer を前提にした記述 (No.36, 41)。
* `Class.forName` によるドライバロード、finally での close (No.59)。try-with-resources がない (No.44)。
* Date / Calendar / SimpleDateFormat が中心で、java.time が「おまけ」扱い (No.28, 30, 40)。
* float + clearfix のレイアウト (No.36)。Flexbox / Grid がない。
* JDBC ドライバ jar の手動追加 (No.58)。Maven / Gradle による依存管理を教えていない。
* バージョンの固定記述: PostgreSQL「現在最新の17.5」(No.51)、Spring Boot 3.5.0 (No.65)、
  JDBC ドライバ 42.7.6 (No.58)。

### 5.4 構成・運用の不整合

* **IDE が途中で 3 回変わる**: VS Code (No.6〜15) → Eclipse (No.16〜63) → VS Code (No.65〜)。
  HTML の章では Sublime Text (No.36)・メモ帳 (No.41) も指示される。切り替える理由と、
  WSL 内の JDK / リポジトリと Windows 側 Eclipse の連携方法の説明がない。
* **提出ルールが矛盾**: No.2「演習問題もスキルチェック同様、gitで提出」/
  No.3「スキルチェックに関しては、Gitでの提出は行わない」/ No.8「スキルチェックはmainブランチ以外で作業」。
  提出先も Slack・スプレッドシート・Git に分散している。
* **順序の逆転**: クラス (No.10) がデータ型 (No.11) より前。継承 (No.24) が、継承を前提にする
  No.22・23 より後。JSP (No.37〜40) がサーブレット (No.41〜43) より前。例外処理 (No.44) が Web の章の途中。
  HTML フォーム (No.47) が GET/POST (No.45, 46) より後。MVC の解説 (No.63) が、MVC で作らせる SC2 (No.62) より後。
  SQL 課題 (No.57) が未習の AS / ORDER BY / AVG を出題。
* **参照先がない記事**: No.20, 21 が参照する「コンストラクタ」の記事、No.9 が参照する「Javaに触れる」の記事は存在しない。
* **スキルチェックに合格基準がない**: SC1・SC2・SC3 のいずれにも合格ライン・評価基準・期限の記述がない。
  SC1 は「課題①〜④」と書きながら本文は ③ まで。
* **第三者素材**: Qiita 記事への手順委任 (No.8, 51, 70)、Qiita 由来画像 2 枚、
  ゲームキャラクター (任天堂作品) を教材例に使用 (No.32)。
