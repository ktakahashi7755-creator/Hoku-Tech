## 4. 負荷試験 (2026-11-06)

方法: `scripts/load-seed.ts` で受講生を追加した専用 DB に本番ビルド (`next start`) を起動し、`scripts/measure.mjs` で計測
(暖機 1 回を除く 5 回の中央値 / 最大値。1 台のコンテナ内で計測)。

| 画面 | 改善前 (受講生 204 名) | 改善後 (204 名) | 改善後 (704 名) |
|------|------------------------|-----------------|-----------------|
| /admin (ダッシュボード) | 2,162 ms | 245 ms | 788 ms |
| /admin/students (一覧) | 2,117 ms | 228 ms | 669 ms |
| /admin/export/students (CSV) | 1,025 ms | 129 ms | 419 ms |
| /home・/progress・レッスン (受講生) | 44〜64 ms | 41〜61 ms | 47〜85 ms |
| 一覧への同時 20 リクエスト (全体) | — | 3.9 秒 | 13.5 秒 |

* 704 名のデータ量: 完了レッスン 9,549 件・理解度チェック 19,022 件・学習記録 19,077 件・提出 2,850 件・採点 2,262 件。
* 改善内容: 受講生ごとに 9 回ずつ発行していたクエリ (N+1) を、テーブルごとに 1 回の一括読み込みに変更。理解度チェックと学習記録はデータベース側で日付ごとに集計してから受け取る。受講生一覧は 50 名ずつ表示。
* 正しさの確認: 改善前の実装と改善後の実装で、全受講生 (704 名と 4 名) の計算結果を比較し、直近 7 日・連続日数・最終学習日時を含めて不一致 0 件。
* 判断: 1 期 200 名規模までは 0.3 秒以内。700 名規模では 1 秒以内だが、同時アクセスが多い場合は集計結果をテーブルに保存する方式 (定期更新) への変更を検討する。
