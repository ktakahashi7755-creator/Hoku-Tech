## 2. 構造上の問題

### 2.1 学習順序

既存の並びには依存関係の逆転が 8 か所ある ([source-audit.md §5.4](source-audit.md))。新しい順序の原則:

```
概念 (なぜ必要か) → 最小の動く例 → 演習 → 応用 → 課題
データ型・変数 → 演算子 → 条件分岐 → ループ → 配列 → メソッド → 例外の基本
クラス → コンストラクタ → カプセル化 → 継承 → オーバーライド → this/super → 抽象クラス/インターフェース → ポリモーフィズム
HTML → CSS → JavaScript → HTTP → フォーム → GET/POST → サーブレット → (JSP 概要) → スコープ/セッション
SQL (DDL → DML → JOIN → 集約 → トランザクション) → JDBC (PreparedStatement 必須) → MVC
```

### 2.2 重複

| 内容 | 既存の重複箇所 | 対応 |
|------|----------------|------|
| クラスとインスタンス | No.5, 10, 20, 21, 22 | 1 レッスンに統合し、他は参照リンクにする |
| アクセス修飾子・カプセル化 | No.10, 20, 21, 22 | 同上 |
| プログラムの実行方法 | No.8, 17, 18 | IDE 方針を決めたうえで 1 本に統合 |
| HTML の基礎 | No.34, 41, 47 | HTML 基礎とフォームの 2 本に再編 |
| 日付の書式化 | No.28, 30, 31 | java.time を主にした 1 本に統合 |
| MVC の説明 | No.63, 66 | MVC の概念 1 本 + Spring での実装 1 本 |
| DB 接続 | No.59, 70 | JDBC 版と Spring 版の違いを明示する |

### 2.3 評価の仕組み

* 合格基準・評価基準・期限が書かれた課題は 0 件。
* 期待出力がテキストで書かれている課題はほぼない (画像のみ。実行日で答えが変わる問題もある)。
* 提出先が Slack / スプレッドシート / Git に分散し、矛盾している。

→ ITS では全課題にルーブリック (要件充足 / 正確性 / 可読性 / 保守性 / テスト / セキュリティ / 説明能力)・
合格点・提出形式 (GitHub リポジトリ URL を基本) を設定する。旧教材の合格基準は流用しない (そもそも記載がない)。

### 2.4 アクセシビリティと保守性

* コードが画像なので、コピー・検索・音声読み上げ・自動テストができない。
* alt テキストなしの画像が 831 枚。WCAG 2.2 の「非テキストコンテンツ」(1.1.1) を満たさない。
* 画像の 85% (712 / 833) が外部ホットリンクで、元データが消えると表示できなくなる。

## 5. 既存教材の強み (残すべき点)

* 各記事が「Step1: 概念を知る → Step2: 使い方を知る」の段階構成で、初心者に入りやすい。
* たとえ話が多い (自動販売機・たい焼き・RPG キャラクター・入館証)。表現を整えれば ITS でも使える。
* 課題が段階的に大きくなる (SQL 課題 → SC2 社員システム → 掲示板 → SC3 図書管理)。
* SC3 は要件 (貸出上限・延滞・返却承認・権限) が具体的で、卒業制作の題材として質が高い。
* 論理削除と物理削除の使い分け (No.56) など、実務寄りの観点がある。
