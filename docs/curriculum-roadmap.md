# ITS ENGINEER ACADEMY — 教育ロードマップ (curriculum-roadmap)

> ステータス: 設計案 v0.1 (2026-11-05)。講師・依頼者のレビュー前。
> 既存 REOrGA 教材との対応は [source-inventory.csv](source-inventory.csv) の `its_level` 列を参照。

---

## 1. 教育目標

IT 完全未経験者が 12 週間 (標準) で、以下を「自分で説明でき、自分で書け、
エラーを自分で切り分けられる」状態になること。

* Java で業務ロジックを書き、単体テストを付けられる
* SQL でテーブル設計と CRUD ができ、SQL インジェクションを防げる
* Spring Boot で認証付きの Web アプリ / REST API を作り、GitHub で PR を出せる
* 仕様書を読んで作業を見積もり、詰まったら適切な形で質問・報告できる
* AI が生成したコードを読み、誤りを見つけて直せる (L8)

## 2. レベル構成と標準週割り

| Level | 名称 | 標準週 | 主な内容 | 既存教材 (No.) | 新規追加が必要な領域 |
|-------|------|--------|----------|----------------|----------------------|
| L0 | IT 入門 | 0.5 | コンピュータの仕組み、ファイルとフォルダ、OS、ネットワークの基礎、学習の進め方 | 1〜3 | コンピュータ/ネットワーク基礎、質問の仕方 |
| L1 | 開発環境・Git | 1 | WSL2、ターミナル、UNIX コマンド、JDK、IDE、Git/GitHub (commit / branch / PR) | 4〜9 | GitHub の PR・Issue・ブランチ運用、SSH 鍵、.gitignore |
| L2 | Java 基礎 | 2 | 変数・データ型・演算子・条件分岐・ループ・配列・メソッド・例外の基本、デバッガ | 10〜15, 20〜21 | デバッガの使い方、エラーメッセージの読み方 |
| L3 | Java 応用・OOP | 2 | クラス・継承・ポリモーフィズム・インターフェース・コレクション・日付 API・パッケージ・単体テスト (JUnit 5) | 22〜33 | JUnit 5、データ構造 (List/Map/Set の選び方)、record、Optional |
| L4 | Web 技術・SQL | 2 | HTML/CSS/JS 基礎、HTTP、Servlet/JSP の概要、RDB 設計、SQL、JDBC | 34〜62 | JavaScript 基礎、HTTP の詳細 (ステータスコード・ヘッダ・Cookie)、テーブル設計・正規化、トランザクション |
| L5 | Spring Boot・API | 2 | MVC、Spring Boot 3、Thymeleaf、Spring Data JPA、Validation、REST API、Spring Security 6 | 63〜72 | REST API 設計、Validation、例外ハンドリング、Spring Security 6 の認証・認可、結合テスト |
| L6 | 実践・チーム開発 | 1.5 | チケット駆動、ブランチ戦略、コードレビュー、仕様書読解、報告・連絡・相談、セキュアコーディング | なし | 全面新規 |
| L7 | 卒業制作・実務能力評価 | 1 | 要件定義〜設計〜実装〜テスト〜発表、講師による実務能力評価 | なし (SC3 が一部相当) | 全面新規 |
| L8 | AI 駆動開発 (将来拡張) | — | 生成 AI 基礎、プロンプト設計、Claude Code、AI 生成コードのレビュー・テスト・デバッグ、情報漏えい対策 | なし | 全面新規 (L7 修了後の追加コース) |

合計 12 週 (L0〜L7)。L8 は別コースとして後から追加する。

### 個別調整

* `enrollments.target_end_date` と週あたり学習可能時間から、レベルごとの目標日を自動算出する。
* 経験者は L0〜L2 の「スキップ判定テスト」に合格すると該当レベルを履修済みにできる
  (合否は講師が最終承認)。
* 理解度テストで基準未満の単元は「復習推奨」として次の学習候補に表示する。

## 3. レッスン標準フォーマット (全レッスン共通)

1. このレッスンでできるようになること
2. 学習目安時間
3. 必要な前提知識 (前提レッスンへのリンク)
4. 初心者向けの概念解説
5. 図解・具体例
6. 動作するサンプルコード (テキスト。実行・テスト済み)
7. 実行結果
8. 自分で試す演習
9. 理解度チェック
10. 実務での利用場面
11. よくあるエラー
12. 復習ポイント
13. 次のレッスン

CMS では 13 項目をブロックとして持ち、未記入の項目は管理画面に警告表示する。

## 4. 評価の流れ

| 段階 | 形式 | 合否判定 |
|------|------|----------|
| 各レッスン | 理解度チェック (選択・記述) | 自動採点 (合格点はレッスンごとに設定) |
| 各レベル末 | 課題 (コード提出 / GitHub リポジトリ提出) | 講師がルーブリックで採点 |
| L2 / L4 / L5 末 | スキルチェック (旧 SC1〜SC3 を再設計) | 講師が採点、再提出可 |
| L7 | 卒業制作 + 発表 + 面談 | 講師 2 名以上による実務能力評価 |

ルーブリック観点: 要件充足 / 正確性 / 可読性 / 保守性 / テスト / セキュリティ / 説明能力 (100 点満点、配点と合格点は課題ごと)。

AI による評価 (L8 以降で導入予定) は補助情報としてのみ扱い、合否は必ず人が判定する。
