## 1. 自動で確認済みのこと (講師が確認しなくてよい)

* サンプルコード 30 件は、実際に実行した出力と掲載した実行結果が一致する (CI で毎回確認)
* 理解度チェックの正解番号が選択肢の範囲内にある・各レッスンに必須の項目 (目標・解説・演習・理解度チェック・よくあるエラー・復習ポイントなど) がある (スキーマで検証)
* 画面の表示崩れ・アクセシビリティの自動検査

## 2. 講師に確認してほしいこと (1 レッスンあたり 10〜20 分が目安)

| 観点 | 確認の問い |
|------|------------|
| A 正確さ | 説明に誤り・古い情報 (バージョン・画面名・コマンド) はないか |
| B 難易度 | IT 未経験の受講生が、前のレッスンまでの知識で理解できるか。説明が飛んでいる箇所はないか |
| C 学習目安時間 | 演習を含めて目安時間で終わるか (長すぎ・短すぎ) |
| D 演習 | 課題文だけで何をすればよいか分かるか。ヒント・解答例は適切か |
| E 理解度チェック | 正解が 1 つに決まるか。本文を読めば答えられるか。合格点は妥当か |
| F よくあるエラー | 実際の受講生がつまずく内容になっているか。抜けている典型的なエラーはないか |
| G 実務との関係 | 「実務での利用場面」が自社の現場の実態と合っているか |

記入例: 結果は「OK」「軽微な修正」「要修正」のいずれか。コメントには観点の記号 (A〜G) を付ける (例: 「E: 問 2 の選択肢 3 も正解に読める」)。

## 6. 確認後の流れ

1. 開発担当がコメントを CMS で反映する (公開中のレッスンを編集しても、公開するまで受講生には旧版が表示される)
2. 修正した版を講師が再確認し、CMS で公開する
3. 全レッスンの確認が終わったら development-progress.md の STEP 3 を「完了」にする
