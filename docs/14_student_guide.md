# 受講者利用ガイド — Hoku Tech

> Hoku Tech をフル活用して12週間でフルスタックエンジニアを目指すためのガイドです。

---

## 1. Hoku Techとは

Hoku Techは、未経験者がAI駆動開発でフルスタックエンジニアを目指す12週間の実践型カリキュラムです。

Hokuが「学習の相棒」として24時間常駐し、エラー相談・コード解説・課題整理・面談練習をサポートします。
ただし、**最終的な評価・合否判定・卒業判定は人間講師**が行います。

---

## 3. Phaseの進め方（1Phase分の手順）

```
1. Phase詳細を開いて「学習目標」を読む
   → 「このPhaseが終わったら何ができるようになるか」を先に確認する

2. Chapter順にLessonを読み進める
   → 読むだけでなく、必ずコードは手元で打って確認する

3. 自己説明チェックをやる
   → 「自分の言葉で説明できるか？」を確認する
   → 説明できなければ再度読む

4. 次のアクションを確認する
   → Lesson後に何をすべきかを見て実行する

5. Assignment（課題）に取り組む
   → 完成コードをコピーするのではなく、自分で実装する
   → 詰まったらHokuに「進め方」を聞く（完成コードを聞かない）

6. Skill Check を受ける
   → Hokuのヒントを参考に、自分の言葉で答えを整理する

7. 講師に進捗報告・課題提出する
```

## 4. Hokuの使い方

### パネルを開く

画面右下の星型アイコン（Hoku）をタップ/クリックするとパネルが開きます。
ドラッグで好きな位置に移動できます。

### 相談カテゴリの選び方

| カテゴリ | こんな時に使う |
|---------|-------------|
| エラー相談 | エラー文が出た・動かない |
| スクショ相談 | 画面が崩れた・表示がおかしい |
| コード解説 | コードの意味が分からない |
| 用語を聞く | 用語の意味を知りたい |
| 課題の進め方 | どこから手をつけていいか分からない |
| GitHub提出前 | 提出前の最終確認をしたい |
| README作成 | READMEの書き方が分からない |
| 面談練習 | 面談での説明を練習したい |
| Claude Code指示文 | AI指示文を作りたい |
| 日報/週報 | 日報・週報の文章を整理したい |

### テンプレートの使い方

1. カテゴリチップを選択する
2. テンプレートが表示される
3. 「Copy」ボタンで内容をコピーする
4. テキスト入力欄に貼り付けて、空欄を埋める
5. 送信する

---

## 5. スクリーンショット相談の方法

**スクショ相談は最もHokuが正確に返答できる相談方法です。**

### 手順

1. 問題が起きている画面をスクリーンショットする
2. ConsoleログやTerminalのログもスクリーンショットまたはコピーする
3. Hokuの「スクショ相談」チップを選択する
4. 📎ボタンでスクショを添付する
5. テキスト欄に「何をしようとしていたか」「何が起きているか」を書く
6. コードの該当部分もあれば一緒に貼る
7. 送信する

### 相談時に一緒に送ると精度が上がるもの

- Console エラー文の全文
- Terminal ログ（Spring Boot/Next.js起動エラーの場合）
- 問題のコード（該当箇所のみ）
- 直前に行った変更内容

> ⚠️ **個人情報・APIキー・パスワードが画像に映り込んでいないか必ず確認してください。**

## 6. AI丸投げ禁止ルール

```
❌ NG: 「この課題のコードを全部作ってください」
✅ OK: 「この課題の要件を整理して、何から始めるか教えて」

❌ NG: Hokuが出したコードをそのままコピー・提出する
✅ OK: コードの意味を理解し、自分の言葉で説明できる状態にする

❌ NG: 分からない部分をすべてHokuに聞いて解決する
✅ OK: まず自分で調べる → 分からなければHokuで状況整理する
```

**なぜ禁止か**:
面談で「このコードを説明してください」と必ず聞かれます。
コードの意味を説明できない場合は不合格になります。
AIに丸投げしたコードは「自分のコード」とは言えません。

## 7. 課題提出の手順

```
1. コードをGitHubにpushする
   git add .
   git commit -m "feat: XX機能の実装"
   git push origin main

2. README.mdを書く（必須項目）
   - 制作物の概要（30字以内のキャッチコピー）
   - 使用技術（バージョン含む）
   - 実装した機能（3〜5項目）
   - 工夫した点
   - 苦戦した点・解決方法
   - AI使用箇所（AI-USAGE.md参照）

3. Hokuの「GitHub提出前チェック」で確認する
   - チェックリスト8項目を全てクリアする

4. 個人情報・APIキー確認
   - git log で過去コミットも確認
   - .env が .gitignore されているか確認

5. 講師にSlack/メールでGitHub URLを送る
```

## 8. 卒業制作（Phase12）の準備

Phase12は「フルスタックアプリ制作」です。

### 開始前に決めること

1. 制作テーマ（P12テーマ一覧を参考に）
2. 使用技術スタック
3. 実装する機能（MVP: 最小限の機能）
4. デプロイ先（Vercel / Heroku等）

### Hokuの活用ポイント

- テーマ選定: 「このテーマで何を作れるか整理して」
- 設計: 「この機能の設計をどう進めるか教えて」
- エラー: 「このエラーの解決順番を整理して」
- README: 「READMEのXX項目をどう書くか一緒に整理して」
- 面談練習: 「このプロジェクトについて面談で聞かれそうな質問を出して」

## 9. 困った時の判断フロー

```
詰まった
  ↓
まず自分で調べる（Google・公式ドキュメント・過去Lesson）
  ↓ 15分以上調べても解決しない
Hokuに相談する
  → 状況・エラー文・スクショをセットで送る
  → 進め方・考え方を整理する
  ↓ HokuのMockアドバイスで解決しない
次の週次面談まで記録しておく（詰まり内容・試したこと）
  ↓
週次面談で講師に相談する
```

**「Hokuに聞いても解決しない」は講師に相談するサインです。**

---

## 10. 面談準備

週次面談前に準備すること:

1. 当週の進捗をまとめる（完了Phase・完了Lesson数）
2. 詰まったポイントと試したことをメモする
3. 課題提出状況を確認する
4. 来週の目標を考える（Hokuの「日報/週報」テンプレートが使える）

面談でよく聞かれること:
- 「このコードのXX行目は何をしていますか？」
- 「なぜこのやり方を選んだのですか？」
- 「このエラーはどうやって解決しましたか？」
