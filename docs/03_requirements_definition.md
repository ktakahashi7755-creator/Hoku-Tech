# 要件定義書 — Hoku Tech

> 実装状態凡例: ✅実装済み / 🔄一部実装 / 📋設計済み/UIのみ / ❌未実装 / 🔮将来拡張

---

## 1. 文書目的

本書はHoku Techの機能・非機能要件を定義する。開発者・PM・講師・法人担当者が共通認識を持つことを目的とする。

---

## 2. プロジェクト背景

未経験者がフルスタック開発を12週間で習得し、AI駆動開発を活用しながら自分の言葉で説明できるエンジニアを育成する。Hoku AIメンターが学習支援を担い、人間講師が最終評価を行う2層構造で、スケーラブルな育成プログラムを実現する。

---

## 3. システム概要

| 項目 | 内容 |
|------|------|
| システム種別 | 静的eラーニングWebアプリ |
| 技術構成 | 単一HTML + Vanilla JS + CSS |
| 配布方法 | HTMLファイル直接配布 |
| ホスティング | サーバー不要（ブラウザ直接起動） |
| データ管理 | data/*.js（window.XXX形式） |
| 進捗保存 | LocalStorage |

---

## 4. 対象ユーザー

| ユーザー種別 | 説明 | 主な利用画面 |
|------------|------|------------|
| 受講者 | 未経験〜転職希望者 | 全画面 |
| 講師 | 課題レビュー・面談担当 | 講師向けページ、課題詳細 |
| 法人担当者 | 導入検討・進捗確認 | 法人向けページ |
| 開発者 | 教材更新・機能追加 | 全ファイル |

---

## 5. 利用シーン

- 受講者が自宅でPhase/Lessonを自習する
- 詰まった時にHokuに相談してエラーの状況整理をする
- スクリーンショットを添付して画面の問題をHokuに見せる（AI連携は将来拡張）
- 課題提出前にHokuの提出前チェックリストを確認する
- 面談練習をHokuと行う
- 講師が週次面談でHoku利用ログを確認する
- 法人担当者が導入前に機能・実績を確認する

## 12. セキュリティ要件

| 要件 | 内容 | 対応状況 |
|------|------|---------|
| APIキー管理 | フロントにAPIキーを直書きしない | 📋（将来AI連携時に必須）|
| 個人情報 | HokuにAPIキー・パスワード・個人情報を送らない旨を明示 | ✅（UI内に明記）|

## 14. 教材要件

- 各Lesson: 学習目標・本文・コード例・自己説明チェック・次のアクションを含む
- 各Phase: 目標・前提知識・期間・チャプター構成を含む
- 各Assignment: 課題目標・要件・提出物・評価基準を含む
- SC: 各Phaseで3〜5問以上の理解度確認問題

## 15. 講師運用要件

---

## 16. Hoku AIメンター要件

- AI丸投げを助長しない設計（考え方を整理する、自分で説明できるよう促す）
- 課題完成コードの丸投げ禁止
- 合否判定・卒業判定を行わない
- 個人情報・APIキー・パスワードを扱わない
- 本物のAI API連携は将来拡張（現状はMock応答）
