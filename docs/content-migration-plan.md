# ITS ENGINEER ACADEMY — 教材移行計画 (content-migration-plan)

> 対象: REOrGA Engineer 公開カリキュラム 72 記事 (https://engineer.reorga.co.jp/curriculum/)
> 根拠データ: [source-inventory.csv](source-inventory.csv) / [source-audit.md](source-audit.md) / [curriculum-gap-analysis.md](curriculum-gap-analysis.md)
> 作成日: 2026-11-05 / ステータス: 計画 (移行作業は未着手)

---

## 1. 移行の基本方針

1. **無計画な複製をしない。** 記事を 1:1 で写すのではなく、ITS の新レッスン構造
   (13 項目の標準フォーマット) に再構成してから取り込む。
2. **出典を必ず保持する。** 移行したすべてのレッスンに `source_url` / `source_post_id` /
   `source_modified_at` / `migrated_at` / `migration_status` を記録する
   (`lesson_versions` に保存。教材を更新しても出典履歴は消えない)。
3. **コード画像はテキスト化して実行検証する。** 既存教材のサンプルコードと実行結果は
   ほぼすべて画像 (Google ドキュメントから貼り付けた `lh7-rt.googleusercontent.com`
   ホットリンク) である。移行時に手で書き起こし、JDK 21 / Spring Boot 3 系で
   実行・テストしたコードだけを掲載する。書き起こせない画像は「要確認」として残す。
4. **画像は自前ストレージへ移す。** 外部ホットリンク画像は URL 失効のリスクがあるため、
   権利確認済みのものだけを ITS 側のストレージへ移し、`alt` テキストを付与する
   (現状 833 枚中 831 枚に alt なし)。
5. **第三者素材は除外または差し替え。** Qiita 由来画像 (2 枚)・外部記事リンクなどは
   権利者確認が取れるまで掲載しない。リンクとしての参照は可。
6. **自動移行は「下書き」まで。** 自動変換したレッスンは必ず `draft` 状態で取り込み、
   講師レビュー (文章品質・画像参照切れ・コード実行可否) を通過したものだけ公開する。

## 2. 分類ルール (維持・改善・再構成・新規追加)

| 分類 | 定義 | 移行時の作業 |
|------|------|--------------|
| 維持 | 内容が正確で、構成も新フォーマットへほぼそのまま載る | 書式変換 + コードのテキスト化 + 画像 alt 付与 |
| 改善 | 内容の骨格は使えるが、説明不足・古い手順・演習不足がある | 上記 + 用語解説・実行結果・よくあるエラー・理解度チェックの追加、古い記述の修正 |
| 再構成 | 1 記事に複数テーマが混在、順序が不自然、または大幅に古い | 分割 / 統合 / 順序変更 / 全面書き直し。旧記事は出典として紐付けのみ |
| 新規追加 | 既存教材に存在しない領域 | ITS で新規執筆 (出典なし) |

記事ごとの分類は [source-inventory.csv](source-inventory.csv) の `classification` 列が正。

## 3. 移行パイプライン (STEP 11 で実装)

```
[1] 取得        WordPress REST API (/wp-json/wp/v2/curriculum) から JSON を取得 (取得済み・72 件)
                 └ 取得日時・modified_gmt を保存。認証が必要な領域には触れない
[2] 正規化      HTML → 構造化ブロック (見出し / 段落 / 画像 / 表 / リスト / リンク)
[3] 画像処理    画像 URL を列挙 → 到達確認 → 権利確認済みのみダウンロード → alt 付与
[4] コード化    画像内コードを人手で書き起こし → tests/ で実行 → 結果を「実行結果」ブロックへ
[5] 再構成      13 項目フォーマットへマッピング。不足項目は「未記入」として明示 (推測で埋めない)
[6] 下書き登録  CMS に draft として登録 (lesson_versions.status = draft)
[7] レビュー    講師チェックリスト: 正確性 / 画像参照切れ / コード実行可否 / 用語説明 / 演習の有無
[8] 公開        レビュー合格分のみ published。公開予約も可
```

各段階の結果は `migration_status` (`fetched` → `normalized` → `assets_ok` →
`code_verified` → `restructured` → `draft` → `reviewed` → `published`) で追跡し、
管理画面から一覧できるようにする。

## 4. 移行の優先順

| 順 | 対象 | 理由 |
|----|------|------|
| 1 | はじめに・環境構築 (No.1〜9) | 受講初日に必要。手順が古いと全員が止まる |
| 2 | Java 初級 (No.10〜15) | 学習の土台。順序の再構成が必要 (クラスの記事がデータ型より前にある) |
| 3 | Java 中級・OOP (No.16〜33) | IDE 手順 (Eclipse) の方針決定後に着手 |
| 4 | HTML/CSS・Servlet/JSP (No.34〜49) | Jakarta EE への読み替えが必要 |
| 5 | DB/SQL・JDBC (No.50〜62) | SQL インジェクション対策 (PreparedStatement) を必須化 |
| 6 | MVC・Spring Boot (No.63〜72) | Spring Boot 3 / Spring Security 6 へ全面更新 |

---

## 5. 移行後の検証項目

* 全レッスンに出典 URL が記録されている (自動テストで検査)
* 画像の参照切れ 0 件 (リンクチェッカーで検査)
* 掲載コードはすべて `content-tests/` で実行・テスト済み
* 13 項目フォーマットの必須項目が埋まっている (空欄は「未記入」として管理画面に表示)
* 旧教材のスキルチェック合格基準を新課題へ機械的に流用していない
