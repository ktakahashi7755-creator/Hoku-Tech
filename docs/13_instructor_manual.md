# 講師運用マニュアル — Hoku Tech

> 対象者: Hoku Techの学習支援を担う人間講師  
> 前提: Hokuは24時間の初歩サポートを担う。講師は「評価・判定・深い理解確認」に集中する。

---

## 1. 講師の役割と位置づけ

Hoku Techでは、学習支援をHokuと人間講師で役割分担します。

| 役割 | Hoku（AI）| 人間講師 |
|------|---------|---------|
| エラー相談（24時間）| ✅ | — |
| コード解説 | ✅ | 必要に応じて |
| 課題進め方の相談 | ✅ 補助 | ✅ 最終確認 |
| **課題合否判定** | ❌ | ✅ |
| **卒業判定** | ❌ | ✅ |
| 面談練習（練習相手）| ✅ | ✅ 本番評価 |
| **AI丸投げ判定** | ❌ | ✅ |
| 週次面談 | — | ✅ |
| 緊急技術相談 | 補助 | ✅ |

## 2. 週次面談フロー

### 事前準備

1. 受講者の当週進捗を確認（LocalStorageデータをスクショで送付してもらう）
2. 提出済みの課題・GitHubURLを確認
3. Hoku相談内容の傾向を確認（提出されたHoku利用ログがあれば）

### 面談進行（30分目安）

| 時間 | 内容 |
|------|------|
| 0-5分 | 当週の進捗確認（完了Phase/Lesson数）|
| 5-15分 | 詰まったポイントのヒアリング・解消 |
| 15-20分 | 課題提出状況・コードの口頭確認 |
| 20-25分 | 次週の目標設定 |
| 25-30分 | 質問・相談対応 |

### 面談後の対応

- 口頭確認で理解不足が発覚した場合 → 再学習指示・再提出
- 進捗が著しく遅れている場合 → フォローアップ計画を立てる
- AIへの丸投げが疑われる場合 → 下記「AI丸投げ判定」を実施

## 4. AI丸投げ判定

### 判定フロー

```
1. 提出コードを確認
2. 口頭確認質問を実施（下記参照）
3. 回答が「まったく説明できない」→ 再提出
4. 「一部分からない」→ 不明点を再学習後、再口頭確認
5. 「説明できる」→ 合格
```

### 口頭確認質問例

```
「このコードのXX行目、何をしているか説明してください」
「なぜここでuseStateを使ったのですか？useRefではダメなのですか？」
「このエラーが出た時、どうやって調べて解決しましたか？」
「このコンポーネントの責務は何ですか？」
「このAPIエンドポイント、なぜこの設計にしたのですか？」
「面談でこのコードについて聞かれたら、どう説明しますか？」
```

### AI丸投げと判定された場合

1. 具体的に「このコードの意味が説明できていません」と伝える
2. 再学習する箇所を具体的に指示する
3. 1週間後に再提出・再口頭確認を実施する
4. 記録として残す（反復する場合は面談で深く話す）

---

## 5. Skill Check確認

Skill CheckはHokuのヒントを見ながら受けるため、合格基準は「自分の言葉で説明できること」。

口頭確認ポイント:
- SC問題に正解できた理由を説明させる
- 「実際の現場ではどう使うか」を答えられるか確認する
- 実装に結びついているか確認する（「分かる」≠「できる」）

## 6. 卒業判定基準

以下を全て満たした受講者を「卒業」とする:

| 項目 | 基準 |
|------|------|
| Phase進捗 | Phase00〜Phase12 全完了 |
| 課題提出 | 全Assignment 合格 |
| 卒業制作 | フルスタックアプリ完成・GitHub公開 |
| ポートフォリオ | README完成・制作物説明あり |
| 口頭確認 | 主要コードを自分の言葉で説明できる |
| 面談練習 | 模擬面談を通過 |
| AI利用ログ | AI-USAGE.md が適切に記録されている |
