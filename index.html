AI 活用ルール

AIを「使われる側」ではなく「使い倒す側」になるための原則。

AI 活用の 6 原則

① 役割・前提・制約・出力形式

4要素が揃ったプロンプトの精度は飛躍的に上がる。

② 出力は必ず自分で読む

1行ずつ目を通す。意味不明な行は聞き返してから採用。

③ AI利用ログを残す

プロンプトと採用判断を記録。面談で「AIをどう使ったか」を語れる状態。

④ 機密情報を貼らない

APIキー・個人情報・社内情報はプロンプトに絶対使わない。

⑤ 自分の言葉で再現できるまで進めない

説明できないコードは「未理解」と同じ。

⑥ レビューする側に回る

「なぜこの書き方か」「他の選択肢は」とAIに問い直す。

週次面談の進め方（30分）

  1. ハイライト確認（5分）：「今週一番できるようになったことは？」から始める。自己肯定感を先に上げる。
  2. 詰まり箇所の解消（10分）：「Hokuに聞いても解決しなかったことは？」で本当に詰まっている箇所を特定。
  3. コードウォーク（10分）：提出物の一部を指差しながら「この部分をなぜこう書きましたか？」と聞く。AI丸投げ検出にも使う。
  4. 次週目標の合意（5分）：「来週の火曜日までにここまでやる、で合ってる？」と受講者に言わせて確認する。

AI丸投げを見抜く質問

口頭1〜2問で、ほぼ確実に検出できます
  • 「このコードの最後の行が何をしているか30秒で説明してください」
  • 「この変数名、なぜこの名前にしましたか？」
  • 「最後にAIに何と聞きましたか？採用・不採用の判断は？」
  • 「このエラーが出た時どうやって解決しましたか？手順を話してください」
  • 「このコードを消して同じものを今書けますか？（実際に書かせる）」

スキルチェック採点方法

スキルチェックは「自分で説明できるか」を重視します。選択問題は正誤で採点、記述問題は以下の基準で採点してください。

  • 4点（十分）：模範解答と同等の内容。具体例や理由も述べられている
  • 3点（合格）：概念の核心を正しく理解している。細かい部分の欠落は許容
  • 2点（要復習）：部分的な理解。重要な概念の混乱がある
  • 1点（要再学習）：理解が不十分。該当レッスンを再受講を推奨

技術スタック選定の理由

Java / Spring Boot を入れる理由

SES案件の40〜60%がJava/Spring Boot。明示的な型付け・OOPの4原則・例外処理が「プロの書き方」を体に染み込ませる。

React / Next.js を入れる理由

フロントエンド案件はReact/Next.jsが業界標準。TypeScript・Server Componentまで含めると差別化になる。

Python / 自動化を入れる理由

業務自動化・データ分析ニーズは急増中。非エンジニア部門への提案やSES単価アップに直結する。

AI駆動開発（Claude Code）を入れる理由

AIを「使う」だけでなく「正しく使う」エンジニアを育成。AI利用ログ文化で品質担保・差別化になる。
